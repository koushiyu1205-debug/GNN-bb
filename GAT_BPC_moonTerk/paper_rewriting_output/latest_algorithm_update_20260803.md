# P0V4+V5 与 QG2 GAT 论文证据更新（2026-08-03）

## 1. 论文中的算法身份

论文当前精确主线采用 `P0V4+V5`：P0V4 是禁止任务点等待的、内存紧凑的原生精确 BPC 回退；V5 在其前增加双向中点负列预处理和根节点 SRI-3 候选分组筛选。双向预处理没有无负列证明权限。只有通过真实对偶、完整分支与割上下文运行的 P0V4 穷举定价可以证明不存在负约化成本列。

根节点 SRI-3 仍是唯一写入论文的割族。V5 最多保留 16 个排序后的候选割，并按 4 组、每组至多 4 个候选依次求解受限主问题。第一组使受限主问题解变为整数，或使受限主问题下界至少增加预设阈值时才提交；否则测试下一组。该筛选是确定性的启发式提交规则，不修改尚未提交时的正式节点界，也不承担割有效性或最优性证明。

双向中点阶段只收集负列见证。在根节点列生成阶段允许接收经过审计的部分搜索见证；在分支树阶段采用保守规则。每条候选列均重新检查分支可行性并按真实对偶重构约化成本。未发现可用负列、审计失败、资源受限或运行异常时，算法回退到 P0V4 精确定价。

## 2. 当前 GAT 候选

正在准备的学习机制为 `QG2` 标签状态 GAT。它仅在 V5 双向中点预处理未返回可用负列之后、P0V4 穷举回退之前调用。每次定价请求至多进行一次 Python 侧推理，产生不可变的节点、弧和标签状态系数；原生求解器据此计算一个标签优先分数。

队列比较顺序为：能否形成终止标签、离散约化成本桶、学习优先分数、精确部分约化成本、创建顺序。学习分数只能改变同一终止类别和同一约化成本桶内的次序。QG2 不过滤标签，不改变可行性、支配、约化成本、界、剪枝、停止条件或证明记录。模型、清单、哈希、数值、分布外或置信门控失败时，运行逐字回退到确定性 Q0 队列。

监督目标对齐到两类可观察里程碑：形成可进入主问题的冻结列批次，或完成穷举定价证明。原始负列首次出现时间仅作为诊断量。候选模型包括线性模型、两层 MLP 和两层轻量 GAT；只有 Oracle、独立实例划分、校准、留出回放、端到端配对和正式验收全部通过后，GAT 性能主张才可进入正文。

## 4. GAT 证据成熟度

先前的 proof-queue GAT、双向预处理门控 GAT 和 one-deviation GAT 均未通过预设部署门槛，不能用作正向性能证据。当前 action-surface-v2 QG2 数据包包含规模 30 和 50 各 150 个候选状态，动作约束、执行冻结和回归测试已通过；截至本次写稿，边界 Oracle 仍在运行，线性/MLP/GAT 训练、校准、留出回放、端到端配对和正式验收尚未完成。正文只可写方法、确切实现边界、开发状态和预注册实验协议。
