========================
Phase 3C：Exact-safe Pruning
========================

目标：
在 Phase 3B 的 exhaustive Pulse DFS 基础上逐步加入 exact-safe pruning。每加入一个 prune，都必须用 brute-force / unpruned Pulse 对照证明不漏负列。

先实现以下 cheap prune，不要实现 LP/MIP bound：

1. Return feasibility pruning：
open-sortie at node i:
energy_used + min_return_energy[i] <= battery
current_time + min_return_time[i] + recharge_lower_bound <= horizon
否则 prune。
注意：如果 no-wait interval 模式下 current_time 不唯一，必须使用安全的最乐观/最保守判断；不确定则 fail-open 不剪。

2. Time-window transition pruning：
对扩展 i -> j，如果所有 path options 都无法在 j due time 前完成服务，则 prune 该 transition。
no-wait 下 arrival < ready_time 的 transition 不可行。
waiting-allowed 下可以等待。

3. Capacity / service-energy pruning：
load + demand_j <= capacity。
energy + travel_energy + service_energy + survival_energy <= battery。
不确定 survival energy 下界时 fail-open。

4. Simple return-cost / adjusted reward bound：
只能作为 cheap fallback。
纯 return_lb - sum(top positive cover duals 很松，不能作为主力。
如果实现 adjusted top-dual reward bound，必须加入 cheap entry/service/return lower cost，且证明它是 safe lower bound。
若 cut/fleet row contribution 不能安全下界化，则该 bound pruning fail-open。

5. Row Contribution Early Correction：
只纳入可安全增量计算或单调累积的 row/cut/fleet/branch contribution。
可能降低 reduced cost 的 row reward 若无安全下界，不能忽略后用于 pruning。
叶子仍必须 manual_journey_reduced_cost true-RC 复算。

Pruning 测试要求：
对每个 prune，新增测试：
- pruned Pulse best_true_rc == unpruned exhaustive Pulse best_true_rc
- pruned Pulse found_negative iff unpruned found_negative
- pruned Pulse exhausted no-negative iff unpruned exhausted no-negative
- prune counters > 0 的 toy case 至少一个
- 当 prune 条件不确定时 fail-open，不应误剪

禁止：
- 不要实现 RPCE/full AMCB/per-label LP/TWR-HK。
- 不要使用 approximate epsilon-dominance。
- 不要用 sorting 结果作为 pruning 条件。

Phase 4：Structural-Key Dominance Archive + Harvesting
========================

目标：
实现 exact-safe Structural-Key Dominance Archive，并接入 Support-Aware Harvesting。注意 proof-search mode 与 harvest-after-negative mode 必须严格隔离。

4.1 Structural-Key Dominance Archive

统一实现一个 archive，不要单独建 Rollback Table 和 Depot Memo Table。

Structural key:
For open_sortie:
- phase
- last_node
- visited_task_mask
- current_sortie_task_mask
- sorties_used
- branch_state_key
- optional time/energy/load bucket only for lookup indexing

For depot_ready:
- phase
- last_node=depot
- visited_task_mask
- sorties_used
- branch_state_key

Archive record:
- partial_reduced_cost lower-bound-safe value
- exact prefix cost if tracked
- current_time or start_interval
- energy_used
- load_used
- trace summary
- insertion serial
- proof_mode flag

Dominance rules:
Waiting-allowed:
P1 dominates P2 only if same structural key and:
- partial_rc(P1) <= partial_rc(P2)
- energy(P1) <= energy(P2)
- load(P1) <= load(P2)
- current_time(P1) <= current_time(P2)
- branch/cut compatibility state no worse

No-wait:
P1 dominates P2 only if same structural key and:
- partial_rc(P1) <= partial_rc(P2)
- energy(P1) <= energy(P2)
- load(P1) <= load(P2)
- start_interval(P1) contains start_interval(P2)

Depot-ready:
P1 dominates P2 if same visited_task_mask, same sorties_used, same branch_state_key, ready_time(P1) <= ready_time(P2), partial_rc(P1) <= partial_rc(P2).

Archive cap:
- If archive full, drop old records only.
- Never discard the current search state because archive is full.
- Overflow is fail-open: less pruning, never unsafe pruning.

Tests:
- waiting-allowed dominance safe
- no-wait earlier-time alone is not dominance
- interval containment dominance safe
- depot-ready dominance removes reordered-equivalent state
- archive cap drops records but does not prune current state
- dominance archive result == unpruned Pulse result on toy

4.2 Support-Aware Harvesting

When Pulse finds the first true-RC negative journey:
- switch to harvest-after-negative mode
- proof certificate for this round becomes impossible
- continue collecting negative candidates only within quota / budget
- call existing harvest_support_aware_negative_journeys()
- return FOUND_NEGATIVE_HARVESTED if harvested nonempty
- never return CERTIFIED_NO_NEGATIVE after harvest mode starts

Diversity Backtracking:
- allowed only in harvest-after-negative mode
- track task_set, sortie masks, first-task sequence, signature, path-option pattern
- subtree quota can stop collecting many same-task-set / high-overlap / replacement-only negatives
- must never mark skipped subtree proof-closed

Tests:
- first negative switches out of proof mode
- diversity backtracking cannot certificate
- harvesting returns only true-RC negatives
- duplicate-only negatives do not certificate
- empty harvest does not certificate
- found-negative status is not global certificate
