# Pressure-aware GAT + Branch/Pricing 优化计划

## 0. 核心目标

本轮目标不是继续扩大 replay，也不是让 GAT 接管 proof，更不是让 GAT 生成 cut。

本轮目标是建立一条新的搜索策略闭环：

```text
GAT prior
  → routeopt_bkf_staged live validation
  → 少量 replay truth check
  → exact BPC proof
```

其中：

```text
GAT 负责搜索策略：
  branch pair prior
  child priority
  pricing pressure 预测
  candidate batch priority
  replay 候选压缩

routeopt_bkf_staged 负责现场验证：
  cheap screen
  child LP probe
  short pricing-pressure probe
  dynamic-K / top-K 控制

replay 负责少量真值校验：
  strict positive
  hard negative
  misleading LP-gain counterexample

exact BPC 负责证明：
  reduced cost
  official lower bound
  no-negative certificate
  fathom / prune
  OPTIMAL
```

## 1. Cut 处理原则

### 1.1 本轮不修改 cut

本轮禁止修改以下内容：

```text
cut validity
cut separator
cut live-add policy
cut coefficient definition
manual_journey_reduced_cost() 语义
pricing cut reduced-cost updater
completion-bound / dominance 的 cut 处理逻辑
certificate / fathom / prune 逻辑
```

cut 线保持独立。cut 必须继续由数学有效不等式驱动，而不是由 GAT 决定。

当前系统的 cut 原则本来就是 pricing-compatible：cut 只有在未来 priced columns 能计算 coefficient 时才允许进入 proof path，因为 cut dual 必须一致进入 reduced cost。

### 1.2 本轮必须记录 cut context

虽然本轮不改 cut，但 GAT/branch/pricing 不能忽略 cut 状态。原因是 cut 会改变：

```text
RMP dual
child LP gain
pricing best reduced cost
negative severity
branch pair 的真实效果
completion-bound retry 行为
```

因此需要把 cut context 作为只读特征记录到 branch/pricing 数据链中。

最小 cut context 字段：

```text
cut_context_signature
cut_context_schema_version
cut_context_active_count
cut_context_subset_row_count
cut_context_weighted_subset_row_count
cut_context_fleet_cut_count
cut_context_dynamic_subset_row_regime
cut_context_dynamic_subset_row_cuts_enabled
cut_context_dynamic_subset_row_cut_gate_enabled
cut_context_cut_dual_nonzero_count
cut_context_cut_dual_abs_sum
cut_context_pricing_supported_all
cut_context_completion_bound_safe
```

说明：

```text
cut_context_signature:
  当前 active cuts 的类型、key、rhs、sense 的稳定 hash。
  不要包含运行时间、随机数或日志路径。

cut_context_schema_version:
  cut context feature schema 版本。
  cut 字段变更时必须 bump。

cut_context_pricing_supported_all:
  所有 active cuts 是否都能被 pricing 正确计算 coefficient。

cut_context_completion_bound_safe:
  在当前 cut dual context 下，completion-bound / profile pruning 是否安全。
  如果不安全，必须 fail-closed。
```

### 1.3 cut 变更后的兼容规则

以后 cut/formulation 线如果新增 live cut，本轮产出的 GAT prior / dataset / score map 不应默认跨 cut regime 使用。

新增兼容规则：

```text
如果 cut_context_schema_version 不匹配：
    pressure-aware prior 不可直接使用；
    fallback baseline / routeopt_bkf_staged 原始流程。

如果 cut_context_signature 未见过或 cut kind 新增：
    GAT prior 只能作为 diagnostic log；
    不参与 selected pair 改写。

如果 active cut 中存在 pricing unsupported cut：
    不允许 pressure-aware prior 进入 official run；
    只能 audit。

如果 cut dual 非零且 completion-bound 对该 cut kind 未声明 safe：
    不允许任何 GAT/prior 影响 certificate path；
    routeopt/pricing 必须 fail-closed。
```

这保证后续 cut 变强时，不会污染当前 GAT/branch/pricing 工作。

## 2. 本轮要解决的问题

当前 V545 已经证明 branch score / replay overlay 有真实收益，但覆盖窄。V545 从 V468 的 `33/60` 提升到 `36/60`，但 566 次 branch decision 中只有 68 次有 selected score，37 次达到阈值，大量节点仍 fallback baseline；报告明确说这不是泛化模型，而是 strict gated replay overlay。

当前 V468/V466 也说明裸模型不可靠，所以不能直接把 GAT score 裸开。V468 报告里，V466 checkpoint 验证 precision、recall、F1 很差，因此没有直接用裸分数，而是用 conservative overlay。

因此本轮要解决：

```text
问题 A：replay 扩库成本高，strict positive 命中率低。
问题 B：branch score 覆盖窄，新 state 大量 fallback。
问题 C：child RMP gain 容易误导，后续 pricing 可能马上找到强负列。
问题 D：GAT true-RC worker 找到很多 negative，但多数 inactive-only。
问题 E：cut 后续可能变化，当前 GAT 数据不能被当前 cut regime 绑定死。
```

## 3. 本轮非目标

本轮不做：

```text
不跑 full60 作为主验收。
不追求 36/60 立刻提升到更高。
不新增 live cut。
不训练需要长时间验证的新大模型作为 production 决策。
不让 GAT 产生 certificate、official bound、fathom 或 prune。
不把 missing pressure 当成真实 0。
不继续盲目扩大 replay 数据。
```

## 4. 主要交付物

### 4.1 Phase2 pricing pressure 字段链闭合

新增并端到端透传以下字段：

```text
phase2_same_child_negative_severity
phase2_separate_child_negative_severity
phase2_negative_severity_sum
phase2_negative_severity_gap
phase2_negative_severity_balance_ratio
phase2_negative_child_presence_balance_gap

phase2_pressure_observed
phase2_same_child_pressure_observed
phase2_separate_child_pressure_observed
```

字段语义：

```text
same_severity = max(0, -phase2_same_child_best_reduced_cost)
separate_severity = max(0, -phase2_separate_child_best_reduced_cost)

phase2_negative_severity_sum =
    same_severity + separate_severity

phase2_negative_severity_gap =
    abs(same_severity - separate_severity)

phase2_negative_severity_balance_ratio =
    min(same_severity, separate_severity) / max(same_severity, separate_severity)

如果 max(severity) <= eps 且 both observed:
    balance_ratio = 1.0

phase2_negative_child_presence_balance_gap =
    abs(1[same child has negative] - 1[separate child has negative])
```

缺失处理：

```text
字段缺失：
    value = 0.0
    observed = 0.0

真实观测到 severity 为 0：
    value = 0.0
    observed = 1.0
```

禁止把 missing 当作真实 0。

### 4.3 Pressure-aware branch prior v0

新增一个 opt-in 的 pressure-aware prior。它不是 production GAT，也不是 proof component。它是 GAT 主力路线的第一版 teacher / baseline。

输出字段：

```text
pressure_prior_score
pressure_prior_components
pressure_prior_rank_before
pressure_prior_rank_after
pressure_prior_missing_reason
pressure_prior_cut_context_signature
pressure_prior_cut_context_compatible
```

v0 scoring 规则可以先用可解释公式：

```text
pressure_prior_score =
    base_branch_score
  + phase1_gain_reward
  - phase2_severity_penalty
  - phase2_balance_penalty
  - width_penalty
  - missing_pressure_penalty
  - cut_context_incompatibility_penalty
```

要求：

```text
known strict positive 不应被降出 top-K；
known hard negative 应被降权；
LP-gain-good 但 phase2 pressure-bad 的 candidate 应被标为 risky；
cut context 不兼容时必须 fail-closed。
```

### 4.4 routeopt_bkf_staged opt-in 接入

新增配置，默认关闭：

```yaml
journey_branch_candidate_pressure_prior_enabled: false
journey_branch_candidate_pressure_prior_weight: 1.0
journey_branch_candidate_pressure_prior_require_observed: true
journey_branch_candidate_pressure_prior_missing_penalty: 1.0
journey_branch_candidate_pressure_prior_require_cut_context_compatible: true
journey_branch_candidate_pressure_prior_log_components: true
```

作用范围：

```text
只影响 candidate ranking / staged testing priority。
不影响 RMP。
不影响 pricing universe。
不影响 certificate。
不影响 cut。
不影响 default config。
```

接入方式：

```text

  → existing score / baseline features
  → pressure prior
  → Phase0 cheap screen
  → Phase1 child LP probe
  → Phase2 short pricing pressure probe
  → routeopt_bkf_staged final selection
```

必须记录：


## 9. 成功标准

本轮成功标准：

```text
1. phase2 pressure 字段端到端闭合。
2. cut context 字段端到端闭合。
3. missing pressure 不再污染为真实 0。
4. pressure prior 可解释、可关闭、默认不启用。
5. routeopt_bkf_staged 日志能解释 rank 变化。
6. known positive branch context 保留在 top-K。
7. hard negative / pressure-bad candidate 被降权。
8. seed61311 无状态回归。
9. seed61635 有 pressure coverage 报告，但不声称解决。
10. 所有新增逻辑不改变 certificate / cut / proof 语义。
```

## 10. 失败标准

出现以下情况视为失败：

```text
1. 新字段只进了 dataset，没有从 solver event 真实透传。
2. missing pressure 被当作真实 0。
3. cut context 不兼容时 pressure prior 仍影响 selected pair。
4. known positive 被 pressure prior 降出 top-K。
5. hard negative 被错误升权。
6. seed61311 从 OPTIMAL 变成非 OPTIMAL。
7. 任何 GAT / pressure prior 影响 official bound、certificate、fathom 或 prune。
8. 任何 cut 逻辑被本轮改动。
9. 报告不能解释 selected pair 为什么改变。
```

## 11. 实现原则

### 11.1 GAT owns search policy

GAT / pressure prior 只负责：

```text
candidate prior
ranking
uncertainty
probe-budget allocation
pricing-pressure prediction
hard-case routing hint
```

### 11.2 Cuts own mathematical relaxation

cut 只由数学有效不等式路线负责：

```text
integer validity
RMP coefficient
pricing reduced-cost updater
manual RC consistency
completion-bound / dominance safety
```

GAT 不能控制 cut。

### 11.3 Exact BPC owns proof

exact BPC 继续负责：

```text
true reduced cost
RMP LP bound
global no-negative certificate
fathom / prune
OPTIMAL
```

GAT 和 pressure prior 不能生成 proof。
